## 2.1用户认证系统

1.Authentication 和 Authorization 有什么区别？

```
Authentication（身份认证）：确认用户身份，例如验证用户名和密码。

Authorization（权限控制）：判断用户是否有权执行某项操作，例如能否删除工单。

身份认证解决用户身份识别问题，权限控制解决用户资源访问和操作授权问题。
```

2.Django 内置 User 模型有什么作用？

```
User 保存基础认证信息
Django 内置 User 已经提供用户名、密码、邮箱、用户状态等字段。
```

3.为什么 TaskFlow 使用 UserProfile 扩展用户信息？

```
通过 Profile 模型扩展用户资料，可以减少对 Django 内置 User 模型的修改，降低认证系统的维护成本。
```

4.Django 的 `create_user()` 和 `User.objects.create()` 有什么区别？

```
create_user()因为它会自动对密码进行哈希处理。也会按照 Django 的用户创建逻辑初始化用户对象。

User.objects.create()不会自动执行 Django 密码哈希流程，可能导致密码以明文形式保存。
```

5.DRF 和 SimpleJWT 分别负责什么？

```
DRF 负责 API，SimpleJWT 负责 JWT 签发和验证。

DRF 主要负责：
- API 请求和响应。
- Serializer 数据校验。
- View 业务处理。
- Authentication 和 Permission 机制。

SimpleJWT 主要负责：
- 签发 Access Token。
- 签发 Refresh Token。
- 验证 JWT。
- 刷新 Token。
- 配合黑名单机制撤销 Refresh Token。
```

## 2.3 JWT 登录与认证流程

### 第 1 题：注册成功后，为什么还需要调用登录接口？

```
注册接口的作用是创建用户账户，将用户信息保存到数据库，并完成密码校验和密码哈希处理。

登录接口的作用是验证用户身份，验证成功后签发 Access Token 和 Refresh Token。

在 TaskFlow 中，注册成功不会自动登录，因此用户还需要调用登录接口，获得 Token 后才能访问需要身份认证的接口。

面试加分点： 注册和登录是两个独立的业务流程，注册成功不代表用户已经完成身份认证。
```

### 第 2 题：登录成功后，为什么还要请求 `/api/auth/me/`？

```
用户登录成功后，后端主要返回 Access Token 和 Refresh Token，并不一定包含前端需要的完整用户资料。因此前端需要携带 Access Token 请求 `/api/auth/me/`，后端通过 JWT 认证识别当前用户，再返回用户 ID、用户名和邮箱等信息，前端将这些信息保存到 Pinia 中，用于页面展示和状态管理。
```

## 第 3 题：Access Token 过期后，前端怎样自动恢复请求？

```
当 Access Token 过期后，后端返回 HTTP 401。前端 Axios 响应拦截器捕获该错误，使用 Refresh Token 请求刷新接口。后端验证 Refresh Token 成功后，签发新的 Access Token 和 Refresh Token，并将旧 Refresh Token 加入黑名单。前端保存新 Token，再使用新的 Access Token 自动重试之前失败的请求。如果刷新失败，则清除本地认证状态并跳转登录页面。

面试加分点： 为了避免多个请求同时遇到 401 时重复刷新，前端使用共享 Promise 或刷新锁，确保并发请求共享同一次刷新操作。
```

### 第 4 题：为什么同时使用 Access Token 和 Refresh Token？

```
同时使用两种 Token，主要是为了兼顾安全性和用户体验。

Access Token 有效期较短，主要用于访问受保护接口。即使发生泄露，其可被使用的时间也相对有限。

Refresh Token 有效期较长，主要用于 Access Token 过期后获取新的 Token，用户不需要频繁重新输入账号密码。

TaskFlow 设置 Access Token 有效期为 30 分钟，Refresh Token 有效期为 7 天，并开启 Refresh Token 轮换和黑名单机制，进一步降低凭证泄露带来的风险。
```

### 第 5 题：为什么退出登录后，不能保证 Access Token 立即失效？

```
因为 TaskFlow 使用的 JWT Access Token 通常采用无状态验证机制。

用户退出登录时，后端主要撤销当前 Refresh Token，并将其加入黑名单。普通 Access Token 不会因为 Refresh Token 被撤销而自动失效。

因此，如果 Access Token 尚未过期，即使用户已经退出登录，攻击者仍可能在剩余有效期内使用该 Token 访问受保护接口。

如果业务要求 Access Token 立即失效，就需要额外实现服务端撤销机制，例如 Access Token 黑名单或 Token 版本控制。
```
